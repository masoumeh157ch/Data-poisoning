# Data Poisoning and Knowledge Corruption in Retrieval-Augmented Generation

**Research Project | Machine Learning Security, Adversarial Attacks, and Retrieval-Augmented Generation (RAG)**

## Overview

This repository contains exploratory research implementations investigating data poisoning, adversarial data manipulation, and the potential impact of knowledge corruption on Retrieval-Augmented Generation (RAG) systems.

The project explores two related areas of machine learning security:

1. **Data Poisoning in Machine Learning:** Preliminary experiments investigating how manipulated training samples and target values affect regression models, alongside exploratory techniques for mitigating their effects.
2. **Knowledge Corruption in RAG Systems:** Development of RAG prototypes and experiments examining how changes in external knowledge can influence the responses generated by Large Language Models (LLMs).

The research was informed by the paper *PoisonedRAG: Knowledge Corruption Attacks to Retrieval-Augmented Generation of Large Language Models* by Zou et al. (2024).

The repository documents an exploratory research and development process rather than a complete reproduction of the original paper. Implementations include independent prototypes, experimental scripts, preliminary evaluations, and supporting research notes.

## Research Motivation

Retrieval-Augmented Generation enhances LLM responses by incorporating information retrieved from external knowledge sources. However, this reliance on external information introduces security risks when the underlying knowledge is inaccurate, manipulated, or intentionally corrupted.

The PoisonedRAG paper demonstrates that attackers can influence generated answers by injecting malicious text into a RAG system's knowledge database.

Motivated by these findings, this project explores the relationship between data integrity, model behavior, and the reliability of retrieval-based language generation.

The main areas of investigation include:

- Understanding the effects of data poisoning on machine learning models.
- Experimenting with different data manipulation strategies.
- Exploring robust regression and anomaly detection techniques.
- Implementing RAG pipelines using different language models and retrieval frameworks.
- Observing how modifications to retrieved knowledge influence LLM-generated responses.
- Exploring approaches for evaluating RAG performance and reliability.

## Project Structure

The research code is organized into two main components.

### 1. Preliminary Data Poisoning Experiments

`preliminary_data_poisoning_experiments/`

This section contains introductory experiments on poisoning attacks against regression models and exploratory defense techniques.

The experiments use synthetic datasets generated from a noisy linear relationship and primarily employ Huber Regression.

**Baseline Model**

- `linear-reg.py`: Establishes a baseline regression experiment using synthetic data and evaluates predictive performance with Mean Squared Error (MSE) and R².

**Data Poisoning Experiments**

- `addoutlier.py`: Injects manually constructed outlier samples to investigate their influence on regression performance.
- `labelflipping.py`: Manipulates selected training target values to examine the impact of corrupted regression targets.
- `gradient-attack.py`: Explores an iterative, residual-based data perturbation procedure that modifies input features and target values.

**Exploratory Defense Techniques**

- `L-F-defense.py`: Applies Isolation Forest to identify and remove anomalous samples from an outlier-contaminated dataset.
- `gradient-defense.py`: Investigates clipping residual-based updates during the data perturbation process.
- `gradient-d2.py`: Combines IQR-based outlier filtering with clipped residual-based perturbations.

**Supporting Notes**

- `poised.txt`: Summarizes several categories of data poisoning attacks and their potential effects on machine learning models.

These scripts are preliminary demonstrations. In particular, the residual-based perturbation experiments should not be interpreted as validated implementations of optimization-based poisoning attacks, and their clipping procedures do not establish the effectiveness of a model-side defense.

### 2. Retrieval-Augmented Generation Implementations

`rag/`

This section contains experimental RAG pipelines developed using different retrieval approaches, language models, inference services, and user interfaces.

**Basic RAG Prototypes**

- `rag.py`: Implements a simple retrieval-and-generation workflow using text matching against a knowledge base.
- `chatbot.py`: Provides a command-line interface for interacting with the basic RAG prototype.
- `groq_rag_cli.py`: Implements a text-based RAG chatbot using Hugging Face embeddings, FAISS, and the Groq API.

**RAG Applications**

- `multilingual_rag.py`: Develops a multilingual RAG chatbot supporting English and Persian queries using language detection, vector retrieval, and Streamlit.
- `adversarial_text_rag.py`: Implements a multilingual RAG application that loads knowledge from a JSON dataset containing an `adv_texts` field, retrieves relevant documents through FAISS, and generates responses using LLaMA through Groq.
- `local_rag_chainlit.py`: Implements a local RAG application using Ollama, FAISS, text chunking, and a Chainlit interface.
- `groq_query.py`: Contains utilities for interacting with Groq-hosted language models and handling API-related errors.

**RAG Evaluation**

- `benchmarking_rag.ipynb`: Explores RAG benchmarking workflows, including question generation, response evaluation, and LLM-based assessment.

**Knowledge Corruption Observations**

- `knowledge_corruption_observations.docx`: Contains recorded examples comparing LLM responses under different knowledge modification scenarios.

The RAG implementations represent different development experiments rather than a single fully integrated application.

## Knowledge Corruption Experiments

One focus of the research was investigating how changes to contextual information could influence the behavior of a retrieval-augmented language model.

The recorded experiments compare model responses across three conditions:

| Condition | Description |
|---|---|
| Original Context | Model response before the investigated modification |
| Partial Modification | Model response after changing a selected word, phrase, or factual value |
| Extensive Modification | Model response after a more substantial modification of the contextual information |

The observations include factual questions involving scientific concepts, historical information, mathematical properties, and general knowledge.

These experiments illustrate that modifying information supplied as context can influence an LLM's generated response.

However, the recorded observations also contain cases where the original response was incorrect or the model did not follow the modified information. Consequently, they should be interpreted as qualitative exploratory observations rather than a validated measurement of attack success.

## Experimental Evaluation

Different components of the repository use different evaluation approaches.

### Regression Experiments

The preliminary data poisoning scripts report:

- **Mean Squared Error (MSE):** Measures prediction error.
- **R² Score:** Evaluates how well the regression model explains variation in the target values.
- **Regression Coefficients:** Provide information about the fitted relationship between input features and target values.

The experiments help illustrate how data manipulation can affect regression behavior.

However, some preliminary scripts split datasets after introducing poisoned samples. Consequently, their reported results are not directly comparable under a standardized clean-test evaluation protocol.

### RAG Evaluation

The benchmarking notebook explores an LLM-assisted evaluation workflow for RAG systems.

The repository also contains qualitative observations of generated responses before and after contextual modifications.

These experiments are exploratory and do not constitute a comprehensive reproduction of the Attack Success Rate (ASR), retrieval metrics, or benchmark results reported in the PoisonedRAG paper.

## Relationship to PoisonedRAG

**Reference Paper:**  
Wei Zou, Runpeng Geng, Binghui Wang, and Jinyuan Jia. *PoisonedRAG: Knowledge Corruption Attacks to Retrieval-Augmented Generation of Large Language Models* (2024).

- Paper: https://arxiv.org/abs/2402.07867
- Official Implementation: https://github.com/sleeepeer/PoisonedRAG

The reference paper investigates knowledge corruption attacks in which malicious texts are introduced into a RAG knowledge database to induce attacker-selected answers.

It studies both black-box and white-box attack settings and emphasizes two conditions for successful attacks:

1. **Retrieval Condition:** The malicious text should be retrieved for the target question.
2. **Generation Condition:** The retrieved malicious text should influence the LLM to generate the attacker-selected answer.

This project was informed by these concepts, particularly the role of external knowledge in shaping LLM responses.

**Scope Clarification:** The implementations in this repository are exploratory experiments inspired by the broader research problem. They are not claimed to reproduce the complete PoisonedRAG attack algorithms, optimization procedures, experimental settings, or reported results.

## Limitations

Several limitations should be considered when interpreting the implementations:

- Some scripts were created as initial proof-of-concept experiments and require additional validation.
- Several RAG implementations depend on external datasets, local text files, model downloads, or inference services.
- Some implementations use older library interfaces and may require updates for compatibility with current versions.
- The preliminary data poisoning experiments do not consistently use identical clean evaluation sets.
- The gradient-related experiments use residual-based perturbations rather than a formally validated poisoning optimization objective.
- The recorded knowledge corruption experiments are qualitative and do not establish statistically validated attack success rates.
- The repository does not provide a complete, end-to-end reproduction of the referenced paper.

These limitations distinguish the exploratory development work from a fully validated research implementation.

## Reproducibility and Configuration

The scripts use multiple experimental configurations and do not share a unified execution environment.

Depending on the implementation, running the experiments may require:

- Installing the relevant Python dependencies.
- Obtaining or preparing the required knowledge-base files.
- Downloading the appropriate embedding or language models.
- Configuring local Ollama models or external LLM inference services.
- Updating deprecated library calls when necessary.
- Supplying API credentials through environment variables.

**Security Note:** API keys, authentication credentials, private datasets, and other sensitive information must not be committed to the repository. Any credentials previously embedded in development scripts should be revoked and replaced before publication.
